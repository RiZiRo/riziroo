# Hyprland config

The compositor half of this desktop. The rest of the repo is the *shell* — the
bar, dock, Island and notifications drawn by Quickshell. This directory is what
Hyprland itself reads: window rules, keybinds, blur, startup.

The two halves are not independent. The glass look in particular only works if
both agree — see [The glass recipe](#the-glass-recipe) below.

## How it loads

Hyprland reads `hyprland.lua` (the `.conf` next to it is an inert stub). That file
sources two trees, in this order:

1. `~/.config/hypr/hyprland/` — upstream's defaults, from
   [end-4's illogical-impulse](https://github.com/end-4/dots-hyprland). **Not in this
   repo**, and replaced wholesale when you update it.
2. `~/.config/hypr/custom/` — everything here. It loads *after* the defaults, so
   **anything set here wins**.

That ordering is the whole design: no upstream file is ever edited, so an upstream
update can never conflict with your changes.

## Install

From the repo root:

```bash
./install.sh --hypr-only     # just this
./install.sh --hypr          # this plus the shell
```

Every file is symlinked back into the checkout, so editing your live config edits
the repo directly — there is no copy-back step to forget. If a real file is already
in the way it is kept as `<name>.bak-<timestamp>` before the link replaces it, and
`~/.config/hypr/hyprland/` is never touched.

Then:

```bash
hyprctl reload && hyprctl configerrors
```

> `hyprctl keyword` does **not** work on a Lua config — it silently does nothing.
> Edit the file and reload. For one-off reads, use `hyprctl eval`.

## What's here

| File | What it does |
|---|---|
| `custom/keybinds.lua` | App launches, Island/shell toggles, display-scale cycling |
| `custom/rules.lua` | Window transparency, per-app opt-outs, the four glass layer rules |
| `custom/general.lua` | Blur noise, xray, flat mouse acceleration |
| `custom/execs.lua` | Startup: portals, VPN, cursor theme |
| `custom/variables.lua` | Browser, file manager, which Quickshell config to run |
| `custom/env.lua` | Cursor theme for XWayland toolkits |
| `hyprlock.conf` / `hypridle.conf` | Lock screen and idle timeouts |
| `monitors.lua.example` | Template for your display layout (see below) |
| `bin/hyprland-session-init` | Brings up `graphical-session.target` and the portals |

Two files the live config needs are deliberately **not** tracked, because something
rewrites them automatically:

- `monitors.lua` — see [below](#monitorslua).
- `hyprlock/colors.conf` — generated by [matugen](https://github.com/InioX/matugen)
  from your wallpaper on every theme change. `hyprlock.conf` sources it on line 1,
  so the installer writes a neutral fallback if it is missing; matugen replaces it
  the next time the colours regenerate.

## The glass recipe

`custom/rules.lua` is the compositor half of the shell's transparency. Quickshell
draws a panel with a translucent fill; Hyprland decides whether to blur what is
behind it. By default it does not, because upstream's `hyprland/rules.lua` sets
`ignore_alpha = 0.79` for the generic `quickshell:.*` namespace — far above those
panels' actual alpha, so every see-through pixel is skipped and the result reads
flat.

Four namespaces get the fix, each with the same three rules:

```lua
hl.layer_rule({ match = { namespace = "quickshell:dock" }, blur = true })
hl.layer_rule({ match = { namespace = "quickshell:dock" }, ignore_alpha = 0.02 })
hl.layer_rule({ match = { namespace = "quickshell:dock" }, xray = false })
```

- `ignore_alpha = 0.02` drops the floor below the panel's own fill, so it gets
  blurred instead of skipped.
- `xray = false` samples the live framebuffer rather than only the wallpaper, so a
  calendar opened over a browser frosts *the browser*.

Applied to `quickshell:dock`, `quickshell:popup`, `quickshell:notificationPopup`
and `quickshell:overview`. Set `xray` back to `true` for a cheaper wallpaper-only
frost.

Window transparency is separate: every window is faded via a `class = ".+"` rule,
with Zen, VLC and Claude Desktop opted back out — video and already-dark UIs look
worse frosted.

## Two scripts rewrite config files

Both edit a file in place, which is intentional — they are how you change a setting
without opening an editor.

- **`custom/scripts/set-scale.sh`** → rewrites the `scale` value in `monitors.lua`.
  `hyprctl keyword` cannot set scale on a Lua config, so the file is the source of
  truth: edit, then reload.
- **`custom/scripts/pin-claude-size.sh`** → rewrites the `claude-desktop-size` rule
  in `custom/rules.lua`. Drag Claude Desktop to the size you want, run the script,
  and that becomes its launch size. The rule must stay on one line spelled
  `size = {"W", "H"}` — that is what the script's `sed` anchors to.

## monitors.lua

Not tracked, on purpose: it is machine-specific *and* `set-scale.sh` rewrites it on
every `Super+Ctrl+S`, which would leave the repo permanently dirty.

The installer copies `monitors.lua.example` into place on a fresh install and leaves
an existing one alone. Find your values with `hyprctl monitors all`.

## Requirements

Beyond Hyprland itself, the scripts here need `jq` (Dolphin scratchpad and Claude
window pinning) and `dolphin` for the scratchpad.

Two keybinds point at scripts that live in `~/.local/bin` and are **not** shipped
here — `Super + A` (`claude-term`) and `Super + Shift + T` (`thumbnail-shot`, which
needs `grim`, `magick` and `wl-copy`). Delete those two binds from
`custom/keybinds.lua` if you do not have them.

`custom/execs.lua` launches AmneziaVPN and sets a `Future-cyan-cursors` cursor
theme — both are personal choices, and harmless to delete.
